# THE FINAL CEO SUMMIT
**Bachelorette Edition**

เว็บโหวตสำหรับมือถือพร้อมหน้าโปรเจกเตอร์และหน้าผู้จัด คะแนนจะอัปเดตจากเซิร์ฟเวอร์เดียวกันทันทีผ่าน Server-Sent Events และเก็บใน SQLite

## เล่นบน Wi-Fi เดียวกัน

1. ใช้คอมพิวเตอร์ที่จะเปิดเว็บเป็นเครื่องหลัก ติดตั้ง Node.js 24 LTS แล้วแตกไฟล์ ZIP และเปิด Terminal ในโฟลเดอร์ `ceo-summit`
2. ให้คอมพิวเตอร์กับมือถือเชื่อม Wi-Fi เดียวกัน บน Mac เปิด System Settings → Wi-Fi → Details → TCP/IP แล้วจด IP Address ของเครื่องหลัก
3. รันคำสั่งต่อไปนี้ ระบบจะแสดงรหัสสำหรับผู้จัด เก็บรหัสนี้ไว้กับผู้จัดเท่านั้น

   ```sh
   npm ci
   export ADMIN_PASSWORD="$(node -e 'process.stdout.write(require("node:crypto").randomBytes(24).toString("hex"))')"
   printf 'Admin password: %s\n' "$ADMIN_PASSWORD"
   read "SUMMIT_IP?IP Address ของเครื่องหลัก: "
   export PUBLIC_ORIGIN="http://${SUMMIT_IP}:8080"
   npm start
   ```

   คำสั่ง `read` ตัวอย่างใช้กับ zsh ให้เปิด Terminal นี้ไว้ตลอดงาน ใช้ HTTP เฉพาะเครือข่าย Wi-Fi ส่วนตัวที่ไว้ใจได้
4. เปิดที่อยู่จาก `PUBLIC_ORIGIN` บนคอมพิวเตอร์ โดยต่อท้ายด้วย `/admin` เพื่อใส่รหัสผู้จัด แล้วกดเปิดหน้าโปรเจกเตอร์จากหน้าแอดมิน เปิดทั้งสองหน้าด้วย IP เดียวกัน
5. ให้เพื่อนหนึ่งคนสแกน QR ที่จอด้วยมือถือก่อนเริ่ม ถ้ามือถือเปิดหน้าโหวตไม่ได้ ให้ตรวจว่า IP ถูกต้อง คอมพิวเตอร์อนุญาตการเชื่อมต่อเข้า และ Wi-Fi อนุญาตให้อุปกรณ์คุยกัน เครือข่าย Guest บางแห่งแยกอุปกรณ์ออกจากกัน

## ลำดับบนเวที

1. ใช้ `/admin` กด **เปิดโหวต** ให้เพื่อนสแกน QR จาก `/projector` เพื่อเข้า `/vote` และให้ครบ 10 คะแนน แต่ละข้อใช้ระดับ 1–5 พร้อมข้อความเสริมได้
2. ดูจำนวนคำตอบสดบนจอ แล้วกด **ปิดโหวต** เมื่อพร้อม
3. กดเปิด KPI ทีละข้อ 10 ครั้ง แล้วกด **เปิดคะแนนรวม** คะแนนรวมคือค่าเฉลี่ยของค่าเฉลี่ยทั้งสิบข้อ ข้อความที่ผู้จัดอนุมัติจะขึ้นจอหลังเปิดคะแนนรวม ผู้จัดกดซ่อนย้อนหลังได้
4. **ล้างคะแนนและเริ่มรอบใหม่** จะลบคะแนนและข้อความของรอบเดิม และให้ทุกคนใช้เบราว์เซอร์เดิมโหวตได้ในรอบใหม่ ระบบเริ่มแต่ละรอบในสถานะปิด

ระบบออกโทเคนสุ่มผ่านคุกกี้เบราว์เซอร์โดยไม่ขอชื่อ และรับหนึ่งคำตอบต่อโทเคนต่อรอบ การลบคุกกี้ เปิดหน้าต่างส่วนตัว หรือเปลี่ยนเบราว์เซอร์อาจทำให้ได้รับโทเคนใหม่

## ใช้งานผ่านอินเทอร์เน็ต

1. เตรียมโฮสต์ที่รัน Docker ได้ มีโดเมน HTTPS และพื้นที่เก็บข้อมูลถาวร ใช้แอปหนึ่ง instance ผู้ให้บริการต้องรองรับการตอบแบบสตรีมต่อเนื่อง
2. สร้างอิมเมจด้วย `docker build -t ceo-summit .`
3. ตั้ง `ADMIN_PASSWORD` เป็นค่าสุ่มยาวอย่างน้อย 20 ตัวอักษรผ่านระบบจัดการความลับของโฮสต์ และตั้ง `PUBLIC_ORIGIN` เป็นโดเมน HTTPS จริงแบบไม่มี path ตัวอย่างต่อไปนี้ใช้ค่าที่เก็บไว้ในตัวแปรสภาพแวดล้อมของเครื่องโฮสต์แล้ว

   ```sh
   docker volume create summit-data
   docker run -d --name ceo-summit --restart unless-stopped \
     -p 127.0.0.1:8080:8080 -v summit-data:/data \
     -e ADMIN_PASSWORD -e PUBLIC_ORIGIN ceo-summit
   ```

4. ตั้ง HTTPS reverse proxy บนโฮสต์ให้ส่งคำขอไปยังพอร์ต 8080 และปิด response buffering สำหรับ `/api/events` ให้ timeout ของการเชื่อมต่อที่ไม่มีข้อมูลยาวกว่า heartbeat 15 วินาที หากใช้โฮสต์ที่จัดการ reverse proxy ให้ ให้ชี้บริการไปยังพอร์ต 8080 ของคอนเทนเนอร์ และเมานต์พื้นที่เก็บข้อมูลที่ `/data`
5. ตรวจ `/admin` และ `/projector` ผ่านโดเมนจริง แล้วสแกน QR จากมือถือบนเครือข่ายอื่นเพื่อทดสอบ `/vote` ก่อนส่งลิงก์ให้เพื่อน หากตั้ง `PUBLIC_ORIGIN` ผิด ให้แก้และเริ่มแอปใหม่

เมื่อกำหนด HTTPS ระบบจะใช้คุกกี้ Secure รหัสผู้จัดตรวจที่เซิร์ฟเวอร์และอยู่ในหน่วยความจำของหน้าแอดมินจนกดออกหรือปิดหน้า บัตรโหวตดิบและข้อความที่ยังไม่อนุมัติไม่ถูกส่งไปยังจอโปรเจกเตอร์

## ตรวจระบบ

`npm test` เปิดเซิร์ฟเวอร์ชั่วคราวและจำลองเบราว์เซอร์ผู้โหวตสองชุด ผู้จัด และจอแยกกัน ครอบคลุมโหวตซ้ำ การปิดโหวต ลำดับการเปิดผล การอนุมัติข้อความ การเก็บข้อมูลหลังรีสตาร์ต และการรีเซ็ตรอบ
